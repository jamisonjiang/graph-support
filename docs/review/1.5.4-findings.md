# 1.5.4 Review Evidence Ledger

## Scope and Rules

This is the first evidence batch, not a completed audit or merge approval. Historical severity
labels and claims that fixes passed tests are not automatically promoted to verified conclusions.
The source excerpts quoted below were reread for this batch. Earlier agent reports remain attributed
reports until independently checked. Production code was not changed for this batch.

All Java and Maven verification MUST run headless. Record the complete command and result for
each run. This batch used source reads and Git operations only.

Every finding records:

| Field | Meaning |
| --- | --- |
| Original claim | Preserve the reported proposition; split compound claims before resolving them. |
| Origin | Reporter, primary assistant inspection, delegated report, or historical summary. |
| Version | Commit plus hashes of relevant working-tree files; HEAD alone is insufficient. |
| Evidence | Read implementation ranges, complete search commands, and retained runtime results. |
| Evidence level | Static inspection, runtime reproduction, inference, or unverified report. |
| Impact and prerequisites | Separate code behavior, input reachability, and possible consequence. |
| Status | Confirmed, partially supported, refuted, unresolved, or fixed pending verification. |
| Remaining verification | A concrete next check, including an old-code failing test where applicable. |

Negative conclusions require an additional field-validation gate: record BOTH the complete search
command (without output-truncating pipes) AND the implementation ranges inspected. Record scope,
exit status, and whether tool output was truncated. If either evidence item is missing, an absence
claim stays unverified. These fields are necessary, not sufficient: a scoped search cannot prove a
global absence or runtime unreachability. Words such as "none", "never", "no", "absent", and their
Chinese equivalents trigger review of this gate; quoting a report is not endorsing its conclusion.

Agreement is not evidence. A topology oracle is not a rendered-intersection oracle. Test success is
not proof of security, optimal layout, or a wall-clock limit. Rechecking an agent report adds evidence
without overwriting the claim's original provenance.

- Remaining verification: attach `actionButton`, service and converter ranges for an end-to-end chain; measure responsiveness before claiming a particular freeze duration.
